# PocketLLM Code Review TODO (post-v0.3.8)

Generated by a full-codebase review of 58 commits and ~8,300 lines of Kotlin/Swift + 1,000 lines of C/C++ across `:app`, `:core`, `:cli`, `ios-app/`, and `app/src/main/cpp/`. Six parallel reviewers produced these findings.

Companion GitHub issue: **#4** — https://github.com/Kimi-syl/PocketLLM/issues/4

**Convention**: each item is a checkbox. The file:line reference is where the defect lives, not where the fix goes. "Agent" identifies which reviewer found it: `common`, `jvm`, `ios`, `android`, `native`, `build`.

## Severity legend

- **CRITICAL** — security, data loss, crash. Block release.
- **HIGH** — real bug under normal use.
- **MEDIUM** — edge case, performance, UX.
- **LOW** — nit, style, or maintenance.

## CRITICAL (21) — block release

### Build (fixes that unblock every later test)

- [ ] **build-native.sh:47** — Copies only `build-native/lib*.so`. With `-DBUILD_SHARED_LIBS=OFF` that's just `libpocketllm.so`; the four other shared libs (`libllama.so`, `libggml.so`, `libggml-base.so`, `libggml-cpu.so`) are **never copied into `jniLibs/arm64-v8a/`**. APK JNI load fails at runtime. *Fix:* copy from `build-native/bin/lib*.so.*` (the versioned symlinks) the way `build-cli-dist.sh` does, then run the SONAME patcher. `[build]`
- [ ] **build-native.sh:22** — `-DCMAKE_PREFIX_PATH="$SCRIPT_DIR/vulkan-host"` references a directory that does not exist in the repo (only `vk-host/`). CMake fails or silently produces no Vulkan support. *Fix:* rename the local dir to `vulkan-host`, or correct the path. `[build]`
- [ ] **build-native.sh:79** — Python SONAME patcher scans the whole .so raw (not just `.dynstr`); any incidental `.so.0` bytes inside `.text`/`.rodata`/`.debug_*` get clobbered. *Fix:* restrict the search to `.dynstr` via `Elf.Structs`, or rely entirely on the CMake `VERSION ""`/`SOVERSION ""` override. `[build]`

### Native C/C++ (crashes)

- [ ] **app/src/main/cpp/opencl_shim.c:167-334** — Every exported `cl*` function only null-checks the per-function pointer, not `g_cl_lib`. **SIGSEGV** when the OpenCL driver is absent (the explicit "fall back to CPU" path). *Fix:* `if (!g_cl_lib) return CL_DEVICE_NOT_FOUND;` at the top of every entry. `[native]`
- [ ] **app/src/main/cpp/vulkan_shim.c:267-272** — `vkGetDeviceProcAddr`, `vkCmdCopyBuffer`, `vkGetPhysicalDeviceFeatures2` silently no-op when `fn==NULL`. ggml-vulkan continues with stale state and crashes inside Vulkan. *Fix:* log error and return `VK_ERROR_INITIALIZATION_FAILED`. Also `vkGetInstanceProcAddr` (262-265) returns NULL silently. `[native]`
- [ ] **app/src/main/cpp/vulkan_shim.c:154-239** — `vulkan_shim_probe` `fork()`s from inside an Android zygote child. JavaVM/malloc/ggml mutexes may be held → child deadlock on `_exit(0)`. *Fix:* `posix_spawn` with `POSIX_SPAWN_SETSID`, or run the probe in a separate process via `android.os.Process.start`. `[native]`

### JNI / llama_jni.cpp (use-after-free, UB, infinite loops)

- [ ] **llama_jni.cpp:62-65** — `dropSession` erases from `gSessions` under `gMutex`, releases the lock, then frees `ctx`/`model`. A concurrent `findSession` that beat the erase holds a raw pointer to a session that gets freed → UAF. *Fix:* free under `gMutex`, or use `std::shared_ptr<Session>` with a refcount. `[native]`
- [ ] **llama_jni.cpp:229-233** — `findSession` releases `gMutex`, then `session->busy.try_lock()` runs without it. `dropSession` can free `session` between the two calls → UAF on `session->busy`. *Fix:* hold `gMutex` while taking the busy lock, or refcount the session. `[native]`
- [ ] **llama_jni.cpp:218-221** — `stopGeneration` does `findSession` then `stopGen.store(true)` with no per-session lock. Same UAF shape. `[native]`
- [ ] **llama_jni.cpp:316-320** — Sampler chain order with grammar: grammar is added **first**, then top_k/top_p/temp/dist. Should be appended **last** (on the temperature-filtered distribution). Current order can produce infinite grammar-violation loops. *Fix:* reorder the `llama_sampler_chain_add` calls so grammar is appended last. `[native]`

### Android security

- [ ] **TlsCertManager.kt:78,40** — Cert marked `CA=true` with `127.0.0.1` in SANs, exported to public Downloads (`exportCertificateToDownloads`). PKCS12 password hard-coded `pocketllm-local`. *Impact:* anyone on the Wi-Fi can install it as a system CA and MitM every HTTPS app on the device. *Fix:* drop the CA flag, drop `127.0.0.1` from SANs, generate a per-install random password stored in Android Keystore, do not export to Downloads. `[android]`
- [ ] **ApiServer.kt:74-100** — Binds `0.0.0.0`, no per-IP rate limit, no body-size cap, `/`, `/health`, `/logs` unauthenticated. LAN attacker pins the engine with one `/v1/chat/completions` POST and pulls the full Bearer-token-spilling log via `/logs?source=file`. *Fix:* bind to `127.0.0.1` by default, gate `/logs` behind `requireApiKey`, add a Netty `HttpObjectAggregator` size cap, add a per-IP rate limit (e.g. bucket4j or a `Semaphore`). `[android]`
- [ ] **core/jvmMain/.../CodeTools.kt:91** — `RunCodeTool` runs `sh -c <arbitrary>` with cwd = app sandbox, but no read/exec restriction. App has read access to `api_keys.json`, `tls.p12`, `app_settings.json` → exfil via `read_url` SSRF (next item). *Fix:* either drop `RunCodeTool` from the CLI, restrict to an explicit allowlist of binaries, or run in a chroot/container. `[jvm]`
- [ ] **core/jvmMain/.../WebFetchTool.kt:81-84** — `read_url` accepts any URL, including `http://169.254.169.254/...`, `http://127.0.0.1`, `file://`. *Fix:* parse URL, reject non-http(s) schemes, resolve host, reject loopback / private / link-local addresses. `[jvm]`
- [ ] **SystemTools.kt:165-181** — `ClipboardReadTool` exfiltrates clipboard content (passwords, 2FA codes) to the model with no consent prompt. *Fix:* gate behind explicit user authorization per session, default OFF. `[android]`
- [ ] **core/src/commonMain/.../ToolGrammarBuilder.kt:38** — Tool/param names interpolated raw into GBNF. A name containing `"`, `\`, or a newline produces invalid GBNF → grammar sampler can hang or crash llama.cpp. *Fix:* reject or sanitize names containing `"`, `\`, control chars, or NULs before emitting. `[common]`

### iOS

- [ ] **LocalEngine.swift:12-13** — `startAccessingSecurityScopedResource()` is released *before* `LlamaContext` is constructed; `llama_model_load_from_file` may fail with a stale/empty path. *Fix:* hold the scope until the engine is destroyed or replaced (retain the URL alongside the engine). `[ios]`
- [ ] **LlamaBridge.mm:138-215** — `dispatch_async` block captures `self` ivars (`_busy`, `_ctx`, `_model`, `_stopGen`) without serializing against `dealloc`. If the engine is released mid-generation the block reads freed memory. *Fix:* retain `self` for the duration of the block, or move ownership to a `std::shared_ptr<Session>`. `[ios]`
- [ ] **LlamaBridge.mm:67** — `path.fileSystemRepresentation` returns NULL for paths with characters unrepresentable in the filesystem encoding; `llama_model_load_from_file` is then handed a NULL pointer (UB, likely crash). *Fix:* fall back to `[path UTF8String]` copied into `std::string`, and check for NULL + surface a typed error. `[ios]`
- [ ] **LlamaBridge.mm:36,42** — `tokens.resize((size_t)-n)` is UB on `INT_MIN`; the resize loop has no upper cap. *Fix:* cast to `int64_t` before negating and cap retries. `[ios]`
- [ ] **LlamaBridge.h:24** — `NSError **` is implicitly non-null under `NS_ASSUME_NONNULL_BEGIN`; Swift can never see the error. Callers always get a generic "load failed" message. *Fix:* annotate as `NSError * _Nullable * _Nullable` or use `NS_SWIFT_THROWS` correctly. `[ios]`

## HIGH (47)

### Native C/C++

- [ ] **opencl_shim.c:97-149** — Driver candidate loop leaks every `h` whose dlsym check fails: on `missing_syms > 0`, the code does `g_cl_lib = NULL` and falls through to the next candidate but never `dlclose(h)`. *Fix:* `dlclose(h)` before `continue`. `[native]`
- [ ] **vulkan_shim.c:248-260,274-282** — `g_instances[8]` and `g_instance_count` are written without bounds check; after 8 instances the array is silently overflowed and `resolve_for` misses the new entry. *Fix:* `if (g_instance_count >= 8) return VK_ERROR_INITIALIZATION_FAILED;`. `[native]`
- [ ] **vulkan_shim.c:248-260** — `resolve_for` only scans the first 8 instances; ggml-vulkan's `vkGetInstanceProcAddr` returning NULL for instance-scoped queries silently no-ops. *Fix:* add error logging + return VK_ERROR_INITIALIZATION_FAILED on missing fns. `[native]`
- [ ] **opencl_shim.c:151-156** — Constructor probes `p_clGetPlatformIDs(0, NULL, &nplat)` after `dlopen` succeeds. If the driver's `.init_array` is half-broken, the probe can crash the constructor. The whole point of the shim is "must NEVER crash on dlopen failure". *Fix:* skip the probe, or run it in a fork. `[native]`
- [ ] **llama_jni.cpp:250-257,283** — `llama_tokenize` returning `nPrompt==0` causes `llama_decode(ctx, llama_batch_get_one(tokens.data(), 0))` → llama.cpp asserts. *Fix:* treat `nPrompt <= 0` as an error before decode. `[native]`

### JNI

- [ ] **llama_jni.cpp:151-153** — On `llama_init_from_model` failure the model is freed, but the bridge returns -1 indistinguishable from "model file not found". Caller cannot distinguish "OOM" vs "bad GGUF". *Fix:* add distinct error codes (file-not-found / invalid-gguf / oom). `[native]`
- [ ] **llama_jni.cpp:253** — `llama_tokenize(..., bos=true, special=true)` causes double-BOS on most SentencePiece tokenizers. *Fix:* pass `bos=false`, let the tokenizer handle it. `[native]`
- [ ] **llama_jni.cpp:260-264** — When `nPrompt >= nCtx`, code erases `(nCtx - 16)` tokens from the **front** of the tokenized prompt, dropping BOS + system-prompt tokens. If `nCtx < 16`, the subtraction underflows to a huge `size_t` and `erase` panics. *Fix:* guard `nCtx >= 16`, truncate from the end of the conversation instead. `[native]`
- [ ] **llama_jni.cpp:266-268** — `GetMethodID` failure returns `nullptr` to Kotlin but `sinkClass` local ref is leaked. *Fix:* `DeleteLocalRef(sinkClass)` before returning. `[native]`
- [ ] **llama_jni.cpp:294-298** — `env->NewByteArray(len)` may throw OOM; code calls `SetByteArrayRegion` on a possibly-NULL array and `CallBooleanMethod` on a pending-exception env. *Fix:* `ExceptionCheck` after `NewByteArray`/`SetByteArrayRegion`. `[native]`
